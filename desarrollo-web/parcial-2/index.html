MÉTODOS Y CÓDIGOS HTTP
  • GET leer · POST crear/enviar · PUT reemplazar · PATCH modificar parte · DELETE borrar · OPTIONS qué se permite.
  • 200 OK · 201 creado · 400 petición mala · 401 sin sesión · 403 sin permiso · 404 no existe · 422 datos inválidos · 500 fallo del servidor · 503 no disponible.
  • Request = método + URL + headers + body (opcional). Response = código + headers + body.
fetch EN 5 LÍNEAS 
const r = await fetch('/api/x', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ a: 1 })
});
if (!r.ok) throw new Error('HTTP ' + r.status);
const datos = await r.json();

Un 404 no rechaza la promesa. Solo un fallo de red.

PLANTILLAS Y ESCAPE
  • Plantilla = HTML con huecos {{dato}}.
  • Datos de fuera (API, usuario) → escapar: & → &amp; · < → &lt; · > → &gt; · " → &quot;.
  • Insertar con textContent; innerHTML solo con HTML que tú controlas.
  • Se escapa el dato, no la plantilla; y al mostrar, no al guardar.
NO CREER AL CLIENTE
  • URL, formulario, JSON, cookies editables: datos de solicitud, no pruebas.
  • Identidad → sesión. Cuenta activa, rol, recurso, dueño, accesos → base de datos.
  • El cliente mejora la experiencia; el servidor repite las validaciones críticas.
  • Consultas con parámetros. Contraseñas con password_hash / password_verify.
ORDEN DE UN LOGIN
  1. ¿método esperado (POST)?
  2. ¿campos presentes y con formato?
  3. ¿la cuenta existe?
  4. password_verify
  5. ¿cuenta activa?
  6. session_regenerate_id(true)

Fallo → mensaje general (no enumerar correos).

XSS Y CSP
  • Almacenado (queda en la BD) · Reflejado (URL/formulario) · DOM (solo en el cliente).
  • CSP: cabecera Content-Security-Policy: default-src 'self' = solo mi mismo origen. *.trusted.com añade ese dominio y subdominios.
CSS Y RESPONSIVE
  • Caja: content → padding → border → margin.
  • Flexbox = 1 dimensión · Grid = 2 (repeat(3, 1fr)).
  • @media (max-width: 768px) = hasta 768 · min-width = desde. Mobile First.
  • Celular hasta 767 · tablet 768–1023 · escritorio 1024+.
JAVASCRIPT
  • const/let (bloque) sobre var (función). === estricto.
  • getElementById · querySelector (primero) · querySelectorAll (todos).
  • addEventListener('submit', e => { e.preventDefault(); … }). Cuidado con scroll y mousemove.

W1 · La web, HTTP y DNS

APLICACIÓN WEB

Software que se usa desde el navegador, sin instalarlo. Un sitio informa; una aplicación hace: inicia sesión, gestiona datos, contenido dinámico.

FRONTEND · BACKEND

Frontend: lo visible, corre en el navegador (HTML, CSS, JS). Backend: corre en el servidor, procesa la lógica, guarda datos y responde al frontend.

INTERNET · IP · DNS

Millones de computadoras con una dirección IP. El DNS es la agenda: traduce google.com a su IP. Un dominio es jerárquico: en www.umg.edu.gt, .gt es el territorial, edu el tipo e umg la organización.

HTTP vs HTTPS

HTTP transfiere hipertexto. HTTPS lo hace cifrando y validando con claves criptográficas (TLS). Por eso se prueba https://google.com contra http://neverssl.com.

Request y response

Request (cliente → servidor)Response (servidor → cliente)
Primera líneaMétodo + URL (GET /recurso?id=1)Código de estado (200 OK, 404 Not Found)
HeadersTipo de contenido, navegador, cookie de sesión…Tipo de contenido, fecha, Set-Cookie, CSP…
BodyOpcional (POST/PUT): formulario o JSONHTML, JSON, una imagen…

W2 · HTML y CSS

ESTRUCTURA HTML

HTML marca y estructura; no tiene lógica. <html> es la raíz con <head> (metadatos, <title>, <link> al CSS) y <body> (lo visible). Las etiquetas correctas dan accesibilidad, mantenimiento y SEO.

HTML SEMÁNTICO

header encabezado · nav navegación · main contenido principal (uno solo) · section tema · article contenido independiente · aside complemento · footer pie.

SEO

<meta name="description" content="…"> (~150 caracteres; no posiciona directo, pero informa). Open Graph controla cómo se ve el enlace al compartirlo: og:title, og:description, og:image, og:url, og:type, og:site_name, og:locale.

ACCESIBILIDAD · WCAG

Cuatro principios: perceptible, operable, comprensible, robusto. <label for="nombre"> enlaza el texto con <input id="nombre">. aria-label da nombre a botones de solo ícono.

FORMULARIOS

form, label, input, textarea, select/option, button. Atributos: action (URL destino), method (post/get), target, name. No se confía en el HTML: el servidor valida otra vez.

CASCADA

El navegador decide qué regla gana por: origen (navegador, usuario, desarrollador), especificidad del selector y orden. Error común: href="style.css" cuando el archivo es styles.css.

Modelo de cajas y layout

styles.css
.card   { margin: 32px; padding: 32px; border: 1px solid #111827; border-radius: 15px; }
#proyectos { margin: 48px 0 0 0; }          /* solo arriba */

@media (max-width: 768px) { .contenedor { flex-direction: column; } }
Margin vs padding

Margin = espacio exterior (separa de los demás). Padding = espacio interior (evita que el texto toque el borde). Usa min-height y no height fijo si el contenido puede crecer; width con max-width. Tarea de la clase 7: conocer em, rem, px, vh, vw, dvh, %.

Responsive ≠ zoom

Es reorganizar el contenido. Mobile First: primero celular, luego estilos para pantallas mayores. Breakpoints: celular hasta 767 px · tablet 768–1023 px · escritorio desde 1024 px.

W3 · JavaScript y DOM

QUÉ ES

Lenguaje que da comportamiento a la página. El DOM es el árbol de nodos que el navegador construye del HTML; JS lo consulta y lo modifica.

TIPOS Y VARIABLES

string, number, boolean, undefined, null, object. var (alcance de función), let (bloque, cambia), const (bloque, no se reasigna). No se usa var salvo que el profe lo indique.

FUNCIÓN FLECHA

const sumar = (a, b) => a + b; Forma compacta; se guarda en una constante.

OPERADORES

Aritméticos, de asignación, de comparación (=== estricto: "1" === 1 es false) y lógicos (&&, ||, !): if (edad >= 18 && edad < 65).

const titulo = document.getElementById('titulo');

  titulo.textContent = 'SE MODIFICÓ';                      // texto seguro

Preguntas que suele hacer la clase
  • Alcance: con let/const dentro del if, console.log(mensaje) fuera lanza error; con var imprime el valor.
  • Event listeners: un click casi no pesa; scroll, mousemove, pointermove, resize se disparan muchísimo: que su función sea liviana. Quita listeners de componentes que se destruyen.
  • Clases: plantilla para varios objetos parecidos (Producto, Usuario). Para un objeto único basta un literal.
  • Objetos: son claves y valores (propiedades y métodos); las respuestas de una API llegan como objetos.

W4 · PHP y APIs

PHP

Lenguaje de scripts de propósito general, pensado para la web. Se ejecuta en el servidor: el cliente solo recibe el resultado. También corre en línea de comandos (tareas con cron).

SESIONES

Cada visitante recibe un identificador de sesión (cookie o URL). session_start() recupera el entorno y $_SESSION guarda datos entre peticiones.

API

Mecanismo para que dos programas se hablen con definiciones y protocolos. Arquitectura cliente–servidor: quien pide es el cliente, quien responde es el servidor.

TIPOS DE API

SOAP (XML, menos flexible) · RPC (llamar una función remota) · WebSocket (bidireccional, JSON) · REST (la más popular y flexible).

basico.php
<?php
echo "Hola, mundo";
if ($edad >= 18) { echo "Eres mayor de edad"; } else { echo "Eres menor de edad"; }
for ($i = 0; $i < 5; $i++) { echo $i; }
$colores = array("rojo", "verde", "azul");
foreach ($colores as $color) { echo $color; }

Formularios: <form action="login.php" method="post"> manda los campos a PHP, que los lee en $_POST (o $_GET). Son datos del cliente: se validan.

W5 · XSS y CSP

Idea clave: XSS ocurre cuando la aplicación no valida ni codifica lo que escribe el usuario y se ejecuta JavaScript malicioso en el navegador de otras personas.

ALMACENADO

El código queda en el servidor/BD y se ejecuta con cada visita (comentarios, publicaciones).

REFLEJADO

Viaja en una URL o formulario y vuelve en la respuesta; se ejecuta cuando la víctima abre el enlace.

BASADO EN DOM

Se ejecuta al modificar el DOM en el cliente; el servidor nunca lo guarda.

ejemplo-xss.html (el de la clase)
boton.addEventListener('click', () => {
  const comentario = input.value;
  resultado.innerHTML = comentario;      // ✗ inyecta HTML: <img src=x onerror=…>
  // resultado.textContent = comentario; // ✓ lo trata como texto
});

Prevención y CSP

  • Validar y codificar lo que se ingresa; no mostrar contenido dinámico sin filtrar; usar librerías seguras.
  • CSP (cabecera HTTP) le dice al navegador qué orígenes se permiten:
CabeceraSignifica
Content-Security-Policy: default-src 'self'Todo del mismo origen del sitio (no subdominios).
… default-src 'self' *.trusted.comMi origen + un dominio de confianza y todos sus subdominios.
… default-src https://onlinebanking.jumbobank.comSolo ese origen, por SSL (evita espiar las solicitudes).

La última diapositiva es un roadmap de ciberseguridad: redes, Linux, IoT, seguridad, ataques (phishing, fuerza bruta, SQL injection, XSS, MITM…) y práctica legal (TryHackMe, Hack The Box, Burp Suite, Nmap, DevTools). No es materia de examen directa deducido.

Bloque 2 · Consumir APIs

A1 · fetch paso a paso

Idea clave: fetch es tu forma de hacer una request desde JavaScript sin recargar la página. Devuelve una promesa que se resuelve con la response; el cuerpo se lee con otra promesa (.json()).

Receta: pedir, comprobar, leer

api.js
async function pedirRecurso(id) {
  try {
    const r = await fetch('/recurso?id=' + encodeURIComponent(id));
    if (r.status === 404) return null;              // un caso esperado
    if (!r.ok) throw new Error('HTTP ' + r.status); // 4xx/5xx NO rechazan solos
    const { resource } = await r.json();           // .json() también es una promesa
    return resource;
  } catch (error) {                                   // red caída, JSON roto, nuestro throw
    console.error(error);
    return null;
  }
}
Quiero…Hago
Enviar JSONheaders: {'Content-Type':'application/json'} + body: JSON.stringify(obj)
Saber si salió bienrespuesta.ok (200–299) o respuesta.status
Leer el cuerpoawait respuesta.json() o .text() (solo una vez)
Varias peticiones a la vezawait Promise.all(ids.map(id => fetch(…)))
Parámetros en la URLnew URLSearchParams({ q: 'a b' }) o encodeURIComponent
Mostrar un mensaje del servidorelemento.textContent = datos.message (nunca innerHTML)
Errores que se ven en el examen
  • Creer que catch atrapa un 404 (no lo hace: revisa ok).
  • Olvidar await (te queda una promesa, no el dato) o mandar el objeto sin JSON.stringify.
  • Olvidar event.preventDefault() en el submit: la página se recarga y no llega la respuesta.
  • Mandar en el body datos que el servidor debe decidir (user_id, rol): ver el caso integral.

Bloque 2 · Plantillas

A3 · Plantillas y escape

Idea clave: una plantilla convierte datos (JSON de una API) en HTML. El peligro es que los datos traen texto de otras personas: si se insertan como HTML, el navegador ejecuta lo que no debe. La defensa es tratarlos como texto.

plantillas.js
const esc = s => String(s).replace(/[&<>"']/g, c =>
  ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' }[c]));

// ✗ inseguro: el dato se vuelve HTML
lista.innerHTML = recursos.map(r => `<li>${r.titulo}</li>`).join('');

// ✓ plantilla con escape al insertar
lista.innerHTML = recursos.map(r => `<li>${esc(r.titulo)}</li>`).join('');

// ✓ sin HTML: crear nodos y usar textContent
const li = document.createElement('li'); li.textContent = r.titulo; lista.append(li);

En PHP es la misma idea: htmlspecialchars($dato, ENT_QUOTES, 'UTF-8'), que es lo que hace el profe en recurso.php.

Demo: el mismo dato, con y sin escape

Edita la plantilla o el comentario. La vista "sin escape" no se dibuja a propósito; se analiza el HTML en un documento inerte y se muestra qué crearía el navegador.

Reglas
  • Escapa al mostrar (contexto HTML), no al guardar en la BD.
  • Los atributos también: title="{{comentario}}" se rompe con una comilla si no se escapa ".
  • Escapar no sustituye a validar, y CSP es una capa extra, no el arreglo.

Las 8 pistas del profe, en una línea

  1. Leer el problema. Para cada dato: ¿quién lo envía? ¿quién puede modificarlo? ¿se cree o se comprueba?

  5. Cambiar contraseña. Usuario de la sesión, cuenta activa, contraseña actual, nueva válida, solo esa cuenta, CSRF y qué sesiones invalidar.
  6. SQL. Una fuente por dato; separar roles y permisos; nombres únicos; NOT NULL; índices en claves foráneas; estados controlados.
  7. Refactor PHP. Decisiones con nombre, retornos tempranos, match; cambiar una dimensión a la vez.
  8. Pruebas manuales. Tabla de solicitud, usuario, dato manipulado, esperado y observado (sección C3).

ResourceService con guard clauses

src/ResourceService.php (propuesta)
final class ResourceService
{
    public function __construct(private PDO $db) {}

    public function show(mixed $id, ?array $user): array
    {
        if ($user === null)        return $this->error(401, 'Debe iniciar sesión');
        if ((int)$user['activo'] !== 1) return $this->error(403, 'Cuenta inactiva');

        $id = filter_var($id, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]);
        if ($id === false)         return $this->error(400, 'ID inválido');

        $recurso = $this->buscar($id);
        if ($recurso === null || !$this->puedeVer($user, $recurso)) {
            return $this->error(404, 'No encontrado');   // mismo mensaje: no revela qué existe
        }
        return ['status' => 200, 'resource' => $recurso];
    }

    private function puedeVer(array $user, array $recurso): bool
    {
        return match (true) {
            $user['rol'] === 'admin'                              => true,
            (int)$recurso['propietario_id'] === (int)$user['id'] => true,
            default => $recurso['estado'] === 'publicado'
                       && $this->tieneAcceso((int)$user['id'], (int)$recurso['id']),
        };
    }

    private function tieneAcceso(int $usuarioId, int $recursoId): bool
    {
        $q = $this->db->prepare('SELECT 1 FROM accesos_recursos
                                 WHERE recurso_id = :r AND usuario_id = :u AND puede_ver = 1');
        $q->execute(['r' => $recursoId, 'u' => $usuarioId]);
        return (bool)$q->fetchColumn();
    }
    private function error(int $status, string $mensaje): array { return ['status' => $status, 'message' => $mensaje]; }
}

if ($user === null)            { http_response_code(401); exit(json_encode(['message' => 'Debe iniciar sesión'])); }
if ((int)$user['activo'] !== 1) { http_response_code(403); exit(json_encode(['message' => 'Cuenta inactiva'])); }

$body = json_decode(file_get_contents('php://input'), true) ?: [];
if (!hash_equals($_SESSION['csrf'] ?? '', (string)($body['csrf'] ?? ''))) {
    http_response_code(403); exit(json_encode(['message' => 'Token CSRF inválido']));
}
$hash = $db->prepare('SELECT password FROM usuarios WHERE id = :id');
$hash->execute(['id' => $user['id']]);
if (!password_verify((string)($body['current_password'] ?? ''), (string)$hash->fetchColumn())) {
    http_response_code(400); exit(json_encode(['message' => 'No se pudo cambiar la contraseña']));
}
$nueva = (string)($body['new_password'] ?? '');
if (strlen($nueva) < 8 || !preg_match('/[A-Za-z]/', $nueva) || !preg_match('/\d/', $nueva)) {
    http_response_code(422); exit(json_encode(['message' => 'La nueva contraseña no cumple los requisitos']));
}
$db->prepare('UPDATE usuarios SET password = :p WHERE id = :id')
   ->execute(['p' => password_hash($nueva, PASSWORD_DEFAULT), 'id' => $user['id']]);
echo json_encode(['message' => 'Contraseña actualizada']);
