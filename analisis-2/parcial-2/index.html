MVC en capas: cada capa es una DLL

En el curso, MVC se implementa en capas físicas: cada capa es un proyecto Class Library que compila a una DLL. Las capas se comunican porque la de arriba tiene una referencia a la DLL de la de abajo. Encima de todo va un proyecto ejecutable que solo arranca el primer formulario.

MODELO

Datos y acceso a la BD

  • Contiene: Entidades (una clase por tabla), Contratos (interfaces del CRUD), Repositorios (conexión y SQL).
  • Conoce a: nadie del proyecto; solo ADO.NET (System.Data.Odbc).
  • Ejemplo: RepositorioEmpleados.Agregar() ejecuta el INSERT.
CONTROLADOR

Reglas y coordinación

  • Contiene: clases con las propiedades que ve la pantalla + validaciones ([Required]…), el EstadoEntidad y los métodos que deciden qué hacer.
  • Conoce a: el Modelo (DLL).
  • Ejemplo: ModeloEmpleado.GrabarCambios().
VISTA

Pantallas

  • Contiene: Formas (formularios), Ayudas (validación con mensajes), controles de usuario.
  • Conoce a: el Controlador (DLL), nunca al Modelo.
  • Ejemplo: FrmEmpleados.btnGrabar_Click.
EJECUCIÓN

Arranque

  • Contiene: Program.cs con Main y Application.Run.
  • Conoce a: solo la Vista (DLL).
  • Tipo: Windows Forms App (WinExe); las otras tres son Library.
Regla de oroCada capa solo conoce a la de abajo. La Vista nunca referencia al Modelo: por eso FrmEmpleados trabaja con ModeloEmpleado (Controlador) y no con la entidad Empleados. Si mañana cambias MySQL por otra BD, solo tocas el Modelo.

Cómo se agrega una referencia (así lo hizo el ingeniero)

  1. Compila la capa de abajo. Clic derecho en el proyecto → Build. Genera bin\Debug\CapaModelo_prototipoumg2k26.dll.
  2. En la capa de arriba: clic derecho en References → Add Reference… → Browse → busca esa DLL → OK.
  3. Usa el namespace: using CapaModelo_prototipoumg2k26.Repositorios; y ya puedes crear sus clases.

¿Y el MDI? Las capas no se unen por MDI

MDI (Multiple Document Interface) es un formulario padre que contiene formularios hijos. Es solo un formulario más de la Vista. En el ERP el MDI vive en Seguridad: FrmMDISeguridad (ventana 2003), dentro de CapaVista_Seguridad. Sus botones laterales abren los demás formularios.

ODBC Unicode de 64 bits

ODBC (Open Database Connectivity) es una capa estándar de Windows. La aplicación no habla directo con MySQL: le pide al Administrador de orígenes de datos ODBC una conexión por DSN, y este usa el driver (MySQL Connector/ODBC 8.0 Unicode) para llegar a MySQL. El DSN guarda servidor, puerto, usuario, contraseña y base de datos; el código solo dice "Dsn=umg_didactica".

Repositorio→OdbcConnection("Dsn=…")→Administrador ODBC→MySQL ODBC 8.0 Unicode Driver→MySQL :3306

Crear el DSN (manual de Consultas)

  1. Instala MySQL Connector/ODBC de 64 bits.
  2. Abre “Orígenes de datos ODBC (64 bits)” y ve a la pestaña DSN de sistema → Agregar.
  3. Elige “MySQL ODBC 8.0 Unicode Driver”.
  4. Data Source Name exacto: EmbutidosS.A (ERP) o umg_didactica (prototipo). TCP/IP localhost, puerto 3306, usuario y contraseña.
  5. Database: la BD del componente (ej. dbConsulta) → Test (“Connection successful”) → OK.
UNICODE VS ANSI

El driver Unicode maneja bien la ñ y las tildes. En el prototipo hay una columna llamada Cumpleaños y textos con tildes: con ANSI se corrompen.

DSN DE SISTEMA VS DE USUARIO

Sistema: lo ve cualquier usuario de Windows (recomendado). Usuario: solo tu cuenta. El manual de Consultas pide sistema (aunque su captura muestra la pestaña de usuario).

32 VS 64 BITS

Hay dos administradores: System32\odbcad32.exe (64 bits) y SysWOW64\odbcad32.exe (32 bits). Un proceso solo ve los DSN de su mismo número de bits. Un WinExe de .NET Framework 4.8 en AnyCPU tiene “Preferir 32 bits” activo por defecto → corre a 32 bits → no ve tu DSN de 64. Solución: Propiedades → Compilar → desmarcar “Preferir 32 bits” o plataforma x64.

ERRORES TÍPICOS
  • IM002: “No se encuentra el nombre del origen de datos…” → el DSN no existe con ese nombre o con esos bits.
  • IM014: discordancia de arquitectura entre el driver y la aplicación → 32 vs 64 bits.
  • 1062 (MySQL): entrada duplicada → PK o UNIQUE repetido.

Los ? son posicionalesODBC no usa nombres de parámetro: enlaza por posición. En UPDATE empleados SET idNumero=?, Nombre=?, Correo=?, Cumpleaños=? WHERE IdPK=? los Add van en ese orden exacto: IdNumero, Nombre, Correo, Cumpleaños y al final IdPK. Los nombres "p_IdNumero" son solo etiquetas.

Seguridad al armar SQL

  • Valores siempre con parámetros ? (nunca concatenados).
  • Nombres de tabla o columna no pueden ir como ?: se validan antes. Consultas usa la regex ^[A-Za-z_][A-Za-z0-9_]*$ y una lista blanca sacada de INFORMATION_SCHEMA.COLUMNS; el Navegador prototipo usa ClsValidaciones.NavegadorMetValidarIdentificador.
  • Contraejemplo: RepositorioComboI concatena "SELECT " + _campo1 + … + _tabla. Funciona porque los valores vienen del código, no del usuario.
  • Seguridad traduce el error 1062 a un mensaje amigable: OdbcEx.Errors[0].NativeError == 1062 → “Ya existe un perfil asignado con esos permisos…” OCR.

3 · Repositorio: la conexión

Clase abstracta (no se instancia sola) que guarda la cadena "Dsn=umg_didactica" y fabrica la conexión. ObtenerConexion() es protected: solo la usan las clases hijas. Crea la conexión pero no la abre. Si cambias de BD, solo tocas esta línea.

Repositorios/Repositorio.cs
using System;
using System.Collections.Generic;
using System.Data.Odbc;
using System.Linq;
using System.Text;
using System.Threading.Tasks;

namespace CapaModelo_prototipoumg2k26.Repositorios
{
    public abstract class Repositorio
    {
        public readonly string connectionString;
        public Repositorio()
        {
            connectionString = "Dsn=umg_didactica";
        }
        protected OdbcConnection ObtenerConexion()
        {
            return new OdbcConnection(connectionString);
        }
    }
}

4 · RepositorioMaestro: cómo ejecutar SQL

También abstracta; hereda de Repositorio. Tiene los dos únicos métodos que ejecutan SQL:

  • EjecucionNonQuery(texto, parámetros, tipo) para INSERT / UPDATE / DELETE: abre, agrega los parámetros con AddRange y devuelve las filas afectadas.
  • EjecucionConsulta(texto, tipo) para SELECT: ExecuteReader() y DataTable.Load(reader).
  • Los using anidados cierran el comando y la conexión aunque haya excepción. CommandType.Text = SQL escrito; StoredProcedure = procedimiento almacenado.
Repositorios/RepositorioMaestro.cs
using System;
using System.Collections.Generic;
using System.Data;
using System.Data.Odbc;
using System.Linq;
using System.Text;
using System.Threading.Tasks;

namespace CapaModelo_prototipoumg2k26.Repositorios
{
    public abstract class RepositorioMaestro : Repositorio
    {
        private DataTable dtTablaDatos; // Establece la tabla de datos para las consultas
        public int EjecucionNonQuery(string _comandoTexto, List<OdbcParameter> _parametros, CommandType _comandoTipo)
        {
            using (var conexion = ObtenerConexion())
            {
                conexion.Open();
                using (var ocComando = new OdbcCommand())
                {
                    ocComando.Connection = conexion;
                    ocComando.CommandText = _comandoTexto;
                    ocComando.CommandType = _comandoTipo;
                    ocComando.Parameters.AddRange(_parametros.ToArray()); // Agregar la colecciòn de paràmetros
                    return ocComando.ExecuteNonQuery();
                }
            }
        }
        public DataTable EjecucionConsulta (string _comandoTexto, CommandType _comandoTipo)
        {
            dtTablaDatos = new DataTable();
            using (var conexion = ObtenerConexion()) //Obtener conexion a la BD
            {
                conexion.Open();
                using (var ocComando = new OdbcCommand())
                {
                    ocComando.Connection = conexion;
                    ocComando.CommandText = _comandoTexto;
                    ocComando.CommandType = _comandoTipo;
                    using (var reader = ocComando.ExecuteReader())
                        dtTablaDatos.Load(reader);  //Llenar la tabla de datos 
                }

Seguridad: quién puede hacer qué, y queda registrado

Seguridad es la base del ERP. Administra empleados, usuarios, perfiles (roles), módulos y aplicaciones; asigna permisos a nivel de formulario y de botón; y registra toda acción en una bitácora de auditoría. Cualquier formulario de otro componente le pregunta a Seguridad si el usuario puede entrar y qué botones habilitar.

Los 4 niveles

Empleado→Usuario→Perfil (rol)→Aplicación dentro de un Módulo
  • Empleado: la persona (DPI, NIT, puesto, correo…).
  • Usuario: la cuenta ligada a un empleado (nombre, contraseña, activo/inactivo).
  • Perfil: el rol (Administrador, Supervisor, Operativo). Un usuario puede tener varios.
  • Módulo y aplicación: las aplicaciones (pantallas) se agrupan en módulos (Producción, Inventario, Ventas, Seguridad).
El modelo de permisosUn permiso es la combinación Rol + Módulo + Aplicación con cuatro derechos: Insertar, Editar, Eliminar, Imprimir (TINYINT 0/1) en tblrolmoduloaplicacion (ventana 2010). Se pueden dar excepciones a un usuario concreto en tblusuariomoduloaplicacion (ventana 2011). Al abrir un formulario se combinan los permisos de todos los roles del usuario en sesión y se habilitan o deshabilitan los botones.

Login y recuperación de contraseña

  1. Credenciales. El Login pide validarlas; se compara contra un hash guardado en la BD.
  2. Perfil y aplicación. Si el hash es válido, se valida el perfil del usuario sobre las aplicaciones y se concede el acceso. Todo va dentro de un bucle [intento < 3].
  3. Con 3 intentos fallidos pasa al flujo de recuperación: se genera un token con tiempo de expiración y se envía por correo.
  4. Código. El usuario escribe el código (6 caracteres, un solo uso; el manual dice que vence en 5 minutos y la pantalla dice 10) y la nueva contraseña dos veces → “Contraseña actualizada”.

La secuencia completa está para dibujar en D7.

Bitácora

Cada alta, modificación o eliminación de cualquier formulario se registra; también LOGIN y LOGOUT. Columnas: ID, Usuario, Acción (LOGIN, LOGOUT, INSERT, UPDATE, DELETE), Tabla afectada, ID registro, Detalles, Dirección IP, Fecha y hora.

Navegador: un CRUD para cualquier tabla

El Navegador es un control de usuario (UserControl) con una barra de 14 botones. Le das el nombre de una tabla y él solo: lee el esquema (columnas, tipos, PK y FK), muestra los registros en un DataGridView y genera el formulario de ingreso y modificación con el control adecuado para cada tipo. Así no programas un CRUD por cada tabla. Se integra con Seguridad para respetar los permisos de insertar, editar, eliminar e imprimir.

public bool NavegadorFuncInsertarRegistro(string NombreTabla, Dictionary<string, string> Datos)
{
    if (Datos == null || Datos.Count == 0) return false;

    ClsValidaciones.NavegadorMetValidarIdentificador(NombreTabla);

    string Columnas = "";
    string Valores = "";
    int Contador = 0;

    foreach (KeyValuePair<string, string> Dato in Datos)
    {
        ClsValidaciones.NavegadorMetValidarIdentificador(Dato.Key);

        if (Contador > 0) { Columnas += ", "; Valores += ", "; }

        Columnas += Dato.Key;
        Valores += "?";
        Contador++;
    }

    string ConsultaSQL = "INSERT INTO " + NombreTabla + " (" + Columnas + ") VALUES (" + Valores + ")";
    OdbcConnection Conexion = _ConexionBD.NavegadorFuncConexion();

    try
    {
        using (OdbcCommand Comando = new OdbcCommand(ConsultaSQL, Conexion))
        {
            int Posicion = 0;

            foreach (KeyValuePair<string, string> Dato in Datos)
            {
                Comando.Parameters.AddWithValue("@p" + Posicion, Dato.Value);
                Posicion++;
            }

            return Comando.ExecuteNonQuery() > 0;
        }
    }
    finally
    {
        _ConexionBD.NavegadorMetDesconexion(Conexion);
    }
}

Respuesta corta

R1Menciona las 3 carpetas de la CapaModelo y qué va en cada una.

Entidades (una clase por tabla), Contratos (interfaces del CRUD) y Repositorios (conexión, ejecución de SQL y el SQL de cada tabla).

R2¿Qué hace GrabarCambios y cómo decide qué operación ejecutar?

Pasa los campos a una entidad y con switch (Estado) llama a Agregar, Editar o Remover; devuelve un mensaje (o el texto de la excepción).

R3¿Por qué la Vista no debe referenciar al Modelo?

Para respetar las capas: si cambia la BD o el SQL, la Vista no se toca; toda regla pasa por el Controlador.

R4Pasos para crear el DSN de 64 bits.

Instalar Connector/ODBC 64 → Orígenes de datos ODBC (64 bits) → DSN de sistema → Agregar → MySQL ODBC 8.0 Unicode Driver → nombre exacto, servidor, puerto, usuario, contraseña, BD → Test → OK.

R5¿Qué es un UserControl? Da dos ejemplos del curso.

Un control propio reutilizable que aparece en el Toolbox al referenciar su DLL: ComboI y el Navegador (también ClsAgregarFiltro y ClsTabla de Consultas).

R6Si agregas una columna a la tabla empleados, ¿qué archivos cambias?

Entidad, los SQL y parámetros de RepositorioEmpleados, el índice en GetAll, la propiedad y reglas de ModeloEmpleado (+ GrabarCambios y GetAll) y los controles y eventos de FrmEmpleados.

R7Resume cómo se integra el Navegador en un formulario del MDI de Seguridad.

Compilar en orden → nuevo Form en CapaVista_Seguridad → Toolbox/Choose Items/CapaVista_Navegador.dll → arrastrar → NavegadorMetConfigurar(tabla, …) → botón del MDI con SeguridadMetTieneAcceso + ShowDialog().

R8Diferencia entre tblrolmoduloaplicacion y tblusuariomoduloaplicacion.

La primera da permisos a un rol (todos sus usuarios); la segunda, a un usuario puntual como excepción.

R9¿Qué se registra en tblbitacora y cuándo?

Usuario, acción, tabla, id del registro, detalle, IP y fecha/hora; en cada LOGIN/LOGOUT y después de cada INSERT/UPDATE/DELETE.

R10¿Qué devuelve FrmConsultasSimples y cómo se lee?

Tras ShowDialog(), si SeleccionRealizada es true, CampoSeleccionado trae el valor del campo identificador de la fila elegida.

R11¿Por qué Seguridad se compila en dos partes al preparar el Navegador?

El Navegador usa Modelo y Controlador de Seguridad (permisos), y la Vista de Seguridad usa la DLL del Navegador: primero M y C de Seguridad, luego Navegador, luego la Vista de Seguridad.

R12Dos defensas contra inyección SQL en Consultas.

Parámetros ? para valores; validar tabla/columna con regex y lista blanca de INFORMATION_SCHEMA; lista blanca de operadores; escape de comodines; solo SELECT/WITH.
