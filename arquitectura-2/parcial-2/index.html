Cómo es el examen deducido de los documentos
  • Es en papel: no hay emulador que te avise de errores. Hay que “ser el procesador”: ejecutar a mano y llevar la tabla de registros.
  • Casi todo es ensamblador 8086 con la sintaxis de EMU8086 que aparece en la hoja de actividades, los labs 2, 4, 5, 6 y 8, el lab de NEG y la evaluación práctica.
  • Tipos de pregunta vistos: ① llenar cuadros de registros después de cada instrucción; ② mapa de memoria y little endian; ③ el cuadro hex / decimal con y sin signo / ASCII / octal / binario; ④ dirección física según el modo de direccionamiento, con una tabla de registros tipo hoja de cálculo (RAX, RBX… CS, SS, ES, DS); ⑤ completar un programa por bloques en una plantilla (el clasificador de caracteres).
  • El profe da los nombres de variables y mensajes; lo que cambia de un examen a otro es la lógica y el valor de N (10 + tu dígito de carné).

Cómo usar esta guía

  1. Lee el bloque 1 con el simulador abierto. Antes de pulsar Paso ▶, di en voz alta qué registro va a cambiar y a qué valor. Activa Ocultar valores para obligarte a predecir: tocas la casilla para comprobar.

  3. Haz las trazas en papel (T1–T7) con lápiz: llena la tabla y luego escríbela para revisarla. Si te trabas, pide una pista o abre el paso a paso.

Hoja de referencia rápida

REGISTROS DE 16 BITS
  • AX acumulador (AH | AL): MUL/DIV, AH = función de INT, AL = tecla leída.
  • BX base (BH | BL): el único general que va entre corchetes. BH = página y BL = color en INT 10h.
  • CX contador (CH | CL): LOOP resta 1 a CX. CX = repeticiones en INT 10h/09h.
  • DX datos (DH | DL): DX = dirección de la cadena (09h, 0Ah), DL = carácter (02h), DH/DL = fila/columna.
  • SI, DI índices (punteros de arreglos) · BP base de pila · SP tope de pila · IP siguiente instrucción.
  • CS código · DS datos · SS pila · ES extra.
DIRECCIÓN FÍSICA
física = segmento × 10h + desplazamiento
  • “Al segmento se le agrega un 0”: DS = 3000h, DI = 0001h → 30001h.
  • Segmento por defecto: IP → CS · SP y BP → SS · BX, SI, DI y [número] → DS. Se cambia con prefijo: CS:[BX], ES:[SI].
  • Little endian: una palabra se guarda con el byte bajo primero. AX = 1DCCh → CC en la dirección, 1D en la siguiente.
  • PUSH: SP − 2 y guarda · POP: lee y SP + 2.
INT 21h (DOS) · función en AH
  • 01h lee una tecla con eco → AL (en ASCII).
  • 02h imprime el carácter de DL (deja AL = DL).
  • 09h imprime la cadena de DS:DX hasta el $ (deja AL = 24h).
  • 0Ah lee una cadena en el búfer DS:DX: [0] máximo · [1] leídos · [2…] caracteres + 0Dh.
  • 4Ch termina el programa (MOV AX, 4C00h o MOV AH, 4Ch).
INT 10h (BIOS de video)
  • MOV AX, 0003h / INT 10h → limpia la pantalla (modo texto 80×25).
  • 02h mueve el cursor a fila DH, columna DL (BH = 0).
  • 03h lee el cursor → DH, DL.
  • 09h escribe AL con el color BL, CX veces, sin mover el cursor.
  • Color = nibble alto fondo, nibble bajo texto: 0Ch = rojo claro sobre negro.
SALTOS (SIN SIGNO)
  • CMP a, b = a − b sin guardar: solo banderas.
  • JE a = b (ZF = 1) · JNE a ≠ b · JB a < b (CF = 1) · JBE a ≤ b · JA a > b · JAE a ≥ b · JMP siempre.
  • LOOP etiqueta: CX = CX − 1 y salta si CX ≠ 0.
  • Los condicionales son cortos (±127 bytes): para lejos, JE VOLVER y en VOLVER un JMP.
MUL · DIV · SHR
  • MUL BL: AX = AL × BL · MUL BX: DX:AX = AX × BX.
  • DIV BL: AX ÷ BL → AL = cociente, AH = residuo (pon MOV AH, 0 antes).
  • DIV BX: DX:AX ÷ BX → AX cociente, DX residuo.
  • No aceptan números: MOV BL, 10 / DIV BL. SHR AL, 1 = ÷ 2.
ASCII QUE SE USA
  • '0'–'9' = 30h–39h · 'A'–'Z' = 41h–5Ah · 'a'–'z' = 61h–7Ah.
  • Espacio 20h · $ 24h · CR 0Dh (13) · LF 0Ah (10) · '*' 2Ah · 'S' 53h · 's' 73h.
  • Dígito ↔ número: ± 30h. Mayúscula ↔ minúscula: ± 20h.
REGLAS DE MOV
  • ✗ memoria → memoria (usa un registro de puente).
  • ✗ número → DS/ES/SS (pasa por AX: MOV AX, @DATA / MOV DS, AX).
  • ✗ cambiar CS con MOV · ✗ tamaños distintos (AX ← BL).
  • Números: sufijo h hex, b binario, o octal; si empieza con letra, un 0 delante (0FFh).

R1 · Los registros

Idea clave: la memoria es un estante enorme; los registros son las manos del procesador. Para sumar, comparar o imprimir, primero tomas el dato en una mano (registro). Por eso casi todo pasa por AX, BX, CX o DX.

La tabla del profe (formato hoja de cálculo)

En el examen suele aparecer el contenido de los registros así, con nombres de 64 bits. Se lee de izquierda a derecha en cuatro grupos de 16 bits; para el 8086 solo importa el último grupo.

CÓMO LEERLA
  • RAX = 0000 0000 0000 1000 → EAX = 0000 1000h → AX = 1000h → AH = 10h, AL = 00h.
  • RCX = …0004 → CX = 0004h → CH = 00h, CL = 04h.
  • RSI = …0100 → SI = 0100h; RDI = …0200 → DI = 0200h.
  • R8 = …0050: registro nuevo de x64 (R8–R15); sus partes son R8D (32), R8W (16) y R8B (8) = 50h. No existe en el 8086.
  • RIP = …4000 → IP = 4000h: la siguiente instrucción está en CS:IP = 0700:4000 → 0B000h.
¿Y BP, SP?
  • Si la tabla no los muestra, el profe no los usa en esa pregunta (o valen 0).
  • Los segmentos van a la derecha: CS 0700, SS 3000, ES 5000, DS 8000. Con ellos se calculan las direcciones físicas (R3).
  • En EMU8086, CS = 0700h es el segmento donde se carga el programa.

Pruébalo: mitades altas y bajas

Predice antes de cada paso. Fíjate en la última: INC DL con DL = FFh vuelve a 00h y DH no se entera.

Comprueba

R1.1Si AX = 3516h, ¿cuánto valen AH y AL?

AH = 35h, AL = 16h. AH son los dos primeros dígitos hex; AL los dos últimos.

R1.2¿Qué registros pueden ir entre corchetes en el 8086?

BX, BP, SI y DI (uno de base y uno de índice como máximo: [BX+SI] sí, [BX+BP] no). [CX] o [AX] no existen.

R1.3¿Por qué IP no aparece en ningún MOV de los programas?

Porque IP no se puede escribir directamente: cambia solo, al avanzar a la siguiente instrucción o con un salto (JMP, JE, LOOP…).

R2 · Segmentos, memoria y pila

El 8086 tiene registros de 16 bits (máximo FFFFh = 64 KB) pero puede direccionar 1 MB (20 bits, 00000h–FFFFFh). La solución: dividir la memoria en segmentos de 64 KB. Una dirección se escribe segmento:desplazamiento y la dirección real (física) es:

física = segmento × 10h + desplazamiento

Multiplicar por 10h en hexadecimal es agregar un 0 a la derecha (como ×10 en decimal). Así lo dice la hoja de actividades: “la dirección inicial del segmento de datos con el cero agregado + el desplazamiento indicado por DI”.

DS:DI = 3000:0001

+00001DI
=30001física

ES:SI = 8000:000A

+0000ASI
=8000Afísica

El mapa de memoria de EMU8086

Botón aux → memory, escribes 3000:0000 y update. Cada fila son 16 bytes: la dirección de la fila, los bytes en hex (el guion separa el 8.º del 9.º) y a la derecha el mismo contenido como caracteres.

La captura de la hoja: en 30000h hay 4Bh (75 = NUMERO1), en 30001h A8h, en 30002h 6Eh, y en 3000Ah–3000Bh la palabra DE26h guardada “al revés”: 26 y luego DE.

Little endian: el byte chico va primero

La pila

Es una zona de memoria en SS que crece hacia abajo (hacia direcciones menores). SP apunta al último dato guardado. Funciona como una pila de platos: el último que entra es el primero que sale (LIFO).

Pruébalo: la hoja de actividades, parte 2

La memoria salta sola a donde se escribe. Compara con lo que pide la hoja: 3000:0001 = 55h (“U”), SS:SP = A000:FFF4, 8000A = CCh y 8000B = 1Dh.

¿Dónde están los datos? (hoja de actividades, parte 3)

En un programa .COM (org 100h) todo vive en un solo segmento.

Si las variables se declaran dentro del código (como NUMERO1 y ARREGLO1 en la hoja), están en el segmento de código: MOV BX, OFFSET NUMERO1 y se buscan en CS:BX. Si antes cambiaste DS a 3000h, en DS:BX no están. Por eso la hoja las copia con prefijo: MOV AH, CS:[BX] / MOV [00H], AH (esta segunda escritura usa DS). OFFSET da el desplazamiento de una variable dentro de su segmento.

Comprueba

R2.1SS = A000h y SP = FFF4h. ¿Dirección física del tope de la pila?

A0000h + FFF4h = AFFF4h.

R2.2Después de MOV [SI], AX con AX = 1C34h y DS:SI = 3000:000A, ¿qué hay en 3000Ah y 3000Bh?

3000Ah = 34h (AL) y 3000Bh = 1Ch (AH).

R2.3¿Cuánto vale SP después de tres PUSH si empezó en FFFEh?

FFFEh − 6 = FFF8h (cada PUSH resta 2).

CÓMO RECONOCER EL MODO
  1. ¿Algún operando tiene [ ] o una variable? No → si el origen es un número: inmediato; si son registros: registro.
  2. Dentro de la dirección, cuenta registros y desplazamiento (número o nombre de arreglo):
  3. solo número → directo · 1 registro → indirecto por registro · 2 registros → base más índice
  4. 1 registro + desplazamiento → relativo a registro · 2 registros + desplazamiento → base relativa más índice
  5. hay un × 2, × 4 u × 8 → índice escalado.
RECETA PARA LA FÍSICA
  1. Elige el segmento: BP → SS, prefijo → el del prefijo, lo demás → DS.
  2. Agrégale un 0 (× 10h).
  3. Suma todos los términos de adentro de los corchetes (registros, número, ARRAY; el escalado se multiplica antes).
  4. Escribe el resultado con 5 dígitos hex.

R4 · Banderas (FLAGS)

Cada bandera es un bit que se prende (1) o se apaga (0) según el resultado de la última operación aritmética. Los saltos condicionales las leen para decidir. En EMU8086 se ven con el botón flags.

BanderaBitSe prende (= 1) cuando…EjemploLa usa
CF acarreo0La operación sin signo se pasó de FFh/FFFFh (suma) o pidió prestado (resta: a < b)FFh + 1 · CMP 30h, 39hJB, JAE, JBE, JA
PF paridad2El byte bajo del resultado tiene una cantidad par de unos03h (0000 0011)—
AF auxiliar4Hubo acarreo del bit 3 al 4 (entre nibbles)0Fh + 1—
ZF cero6El resultado es 0 (en CMP: son iguales)CMP AL, ALJE, JNE, JBE, JA
SF signo7El bit más alto del resultado es 1 (negativo con signo)NEG 26h = DAhJL, JG…
TF trampa8Ejecución paso a paso (depuración)——
IF interrupciones9Interrupciones habilitadas (normalmente 1)——
DF dirección10Instrucciones de cadena recorren hacia atrás——
OF desbordamiento11La operación con signo se salió de rango (−128…127)7Fh + 1 = 80hJL, JG, JO
QUÉ INSTRUCCIONES LAS CAMBIAN
  • ADD, SUB, CMP, NEG: todas (CF, ZF, SF, OF, PF, AF).
  • INC, DEC: todas menos CF.
  • MUL: CF = OF = 1 si la parte alta (AH o DX) quedó ≠ 0; las demás quedan indefinidas.
  • SHR: CF = el bit que salió.
  • MOV, LEA, PUSH, POP, LOOP, JMP, Jxx, INT 21h: no las tocan.
CF vs OF: LA TRAMPA
  • 7Fh + 1 = 80h: sin signo 127 + 1 = 128, cabe → CF = 0. Con signo +127 + 1 = −128 → OF = 1, SF = 1.
  • FFh + 1 = 00h: sin signo 255 + 1 = 256, no cabe → CF = 1, ZF = 1. Con signo −1 + 1 = 0 → OF = 0.
  • CF es para números sin signo; OF para números con signo.

Pruébalo

R4.1Después de NEG BL con BL = 26h, ¿se activó la bandera de signo? (pregunta de la hoja)

Sí. DAh = 1101 1010: el bit 7 es 1 → SF = 1. Además CF = 1 (NEG de algo distinto de 0).

R4.2CMP AL, BL con AL = BL. ¿Qué bandera se prende y qué salto se toma: JE o JB?

ZF = 1 (la resta da 0) y JE salta. JB no (CF = 0).

Bloque 1 · El procesador

R5 · Números y complemento a 2

La hoja de actividades pide un cuadro con seis formatos del mismo valor: hexadecimal, decimal con signo, decimal sin signo, carácter ASCII, octal y binario. Estas son las recetas para hacerlo a mano.

HEX ↔ DECIMAL
  • Hex → dec: cada dígito por su potencia de 16. 26h = 2×16 + 6 = 38. 1DCCh = 1×4096 + 13×256 + 12×16 + 12 = 7628.
  • Dec → hex: divide entre 16 y lee los residuos de abajo hacia arriba. 7628 ÷ 16 = 476 r 12 (C) · 476 ÷ 16 = 29 r 12 (C) · 29 ÷ 16 = 1 r 13 (D) · 1 → 1DCCh.
  • Potencias: 16² = 256 · 16³ = 4096 · 16⁴ = 65536.
BINARIO Y OCTAL
  • Hex → binario: cada dígito hex son 4 bits. 26h = 0010 0110.
  • Binario → octal: grupos de 3 desde la derecha. 00 100 110 → 46 (octal).
  • Sufijo o = octal: MOV SI, 12o → 1×8 + 2 = 10 = 000Ah (la hoja lo usa).
COMPLEMENTO A 2 (NEG)
  • Invertir todos los bits y sumar 1. 26h = 0010 0110 → 1101 1001 → +1 → 1101 1010 = DAh.
  • Atajo en hex: 100h − 26h = DAh (8 bits) · 10000h − 26h = FFDAh (16 bits).
  • NEG dos veces regresa al original: NEG FFDAh = 0026h.
¿CON O SIN SIGNO?
  • Los bits son los mismos; cambia la interpretación.
  • Sin signo: DAh = 218 · FFDAh = 65498.
  • Con signo: si el bit más alto es 1, es negativo: valor − 256 (8 bits) o − 65536 (16 bits). DAh = 218 − 256 = −38.
  • Rangos: 8 bits 0…255 / −128…127 · 16 bits 0…65535 / −32768…32767.

ANATOMÍA DE UNA LÍNEA 
CAPTURA:  MOV AH, 01h   ; leer caracter con eco
  • Etiqueta (opcional, termina en :) · mnemónico · destino, origen · ; comentario.
  • El destino siempre va primero: MOV destino, origen.
  • Mayúsculas y minúsculas dan igual, excepto dentro de comillas ('S' ≠ 's').
¿POR QUÉ MOV AX, @DATA / MOV DS, AX?
  • En un .EXE, al arrancar, DS apunta al PSP (una zona de DOS), no a tus variables.
  • El 8086 no permite MOV DS, @DATA (número → segmento): se pasa por AX.
  • Si lo olvidas, INT 21h/09h imprime basura: busca el mensaje en el segmento equivocado.
  • En un .COM no hace falta: CS = DS = ES = SS desde el inicio.

MOV destino, origen copia: el origen se queda igual. Los dos operandos deben ser del mismo tamaño.

Dirección vs. contenido

LEA DX, MSJ

DX ← dirección de MSJ. Es lo que necesita INT 21h/09h.

MOV DX, OFFSET MSJ

Lo mismo: DX ← dirección. Los labs usan esta forma; el examen, LEA.

MOV DL, CANT_NUMS

DL ← contenido de la variable (el número guardado ahí).

Con arreglos: MOV AL, buffer[2 + si] lee el byte en buffer + 2 + SI; MOV DL, [SI] lee el byte al que apunta SI; MOV CL, buffer[1] lee el segundo byte del búfer.

PUSH y POP

  • PUSH reg16: SP = SP − 2 y guarda el registro en SS:SP. POP reg16: lee SS:SP y SP = SP + 2.
  • Solo trabajan con 16 bits (PUSH CX sí; PUSH CL no).
  • Uso típico del curso: guardar CX mientras algo adentro del ciclo lo usa (Lab 8), o pasar un valor de un registro a otro (PUSH AX … POP CX).
  • Sale en orden inverso: si haces PUSH AX y PUSH BX, el primer POP recibe lo de BX.
L2.1Después de la demo, ¿AX y CX quedaron como al principio?

No: quedaron intercambiados. AX = 5500h y CX = 3516h, porque el primer POP saca lo último que entró (CX).

L4 · Comparar y saltar

CMP a, b hace a − b sin guardar el resultado: solo deja las banderas. El salto que va justo después decide mirando esas banderas. Truco para leerlos: Jump if Below (menor), Above (mayor), Equal (igual), Not.

SaltoSalta si (después de CMP a, b)BanderasEn los documentos
JE (= JZ)a = bZF = 1JE VOLVER, je fin
JNE (= JNZ)a ≠ bZF = 0JNE MAY_LISTAR
JBa < b (sin signo)CF = 1jb no_valido
JBEa ≤ bCF = 1 o ZF = 1jbe estado_bajo
JAa > bCF = 0 y ZF = 0ja no_valido
JAEa ≥ bCF = 0(equivalente; no aparece)
JMPsiempre—jmp inicio

Los caracteres ASCII son números sin signo: por eso el curso usa JB/JA. JL/JG (con signo) no aparecen en los documentos.

La cascada de rangos del examen

Bloque 1 del examen (clasificación)
CMP AL, '0'
JB ES_ESPEC      ; menor que '0'
CMP AL, '9'
JBE ES_NUM       ; '0'..'9'
CMP AL, 'A'
JB ES_ESPEC      ; entre '9' y 'A'
CMP AL, 'Z'
JBE ES_MAYUS     ; 'A'..'Z'
CMP AL, 'a'
JB ES_ESPEC      ; entre 'Z' y 'a'
CMP AL, 'z'
JBE ES_MINUS     ; 'a'..'z'
JMP ES_ESPEC     ; mayor que 'z'
REGLAS DE ORO
  • Después de cada rama, JMP a la salida o a SIGUIENTE; si no, la ejecución “se cae” a la etiqueta de abajo.
  • La última rama puede quedar sin JMP si justo abajo está la salida (ES_ESPEC en el examen).
  • Para validar un rango: CMP AL, '0' / JB no_valido / CMP AL, '9' / JA no_valido.
  • Salto corto: JE, JB… solo llegan a ±127 bytes. Para ir lejos: JE VOLVER … VOLVER: JMP INICIO_PROGRAMA.

Pruébalo: ¿qué rama toma 'm'?

BL termina en 2 (mayúscula), 3 (minúscula) o 4 (especial). Cambia mentalmente AL y predice el camino.

Bloque 3 · Patrones del profe

P1 · Escenarios del examen

Estos son los tipos de pregunta que salen de sus documentos. Aprende a reconocerlos en el enunciado y ten la receta lista.

E1 · TABLA DE REGISTROS

Lo reconoces por: “llene el cuadro con el contenido hexadecimal y su equivalente decimal” después de una lista de instrucciones.

Receta: una fila por instrucción; solo cambia el destino (y en MUL/DIV/PUSH/POP, los implícitos). Copia lo demás. Decimal: expande en potencias de 16.

Practica: T1, T2, T4

E2 · MAPA DE MEMORIA

Lo reconoces por: “abra su mapa de memoria en 3000:0001… ¿qué valor contiene la dirección?”

Receta: física = segmento con un 0 + desplazamiento. Palabras: byte bajo en la dirección, alto en la siguiente.

Practica: T2, T6

E3 · CUADRO DE SEIS FORMATOS

Lo reconoces por: columnas Hexadecimal · Decimal con signo · sin signo · ASCII · Octal · Binario, casi siempre con NEG.

Receta: binario desde el hex (4 bits por dígito), octal en grupos de 3, signo por el bit alto (valor − 256).

Practica: T3 · Conversor

E4 · DIRECCIÓN FÍSICA POR MODO

Lo reconoces por: una tabla de registros (RAX … RIP, CS SS ES DS) y la tabla de modos de direccionamiento.

Receta: identifica el modo, elige el segmento (BP → SS), agrega el 0 y suma.

Practica: D1–D15

E5 · ¿DÓNDE ESTÁN LOS DATOS?

Lo reconoces por: MOV BX, OFFSET NUMERO1, “búsquelo en CS:BX… ¿y en DS:BX?”, CS:[DI].

Receta: en un .COM las variables viven en CS; OFFSET es el desplazamiento; el prefijo CS: lee de ahí aunque DS apunte a otro lado.

Practica: T6 · E16

E6 · PLANTILLA POR BLOQUES

Lo reconoces por: “EVALUACIÓN PRÁCTICA… BLOQUE 1: CAPTURA Y CLASIFICACIÓN · Instrucciones: …”.

Receta: bloque 1 = LOOP con cascada y búferes indexados con BX; bloque 2 = por categoría: etiqueta, DIV entre 10, lista con SI; bloque 3 = S/s.

Practica: E20, E21

E7 · VALIDAR Y CLASIFICAR

Lo reconoces por: “ingrese un dígito del 0 al 9”, estados bajo / estable / crítico, “valor inválido”.

Receta: CMP '0' + JB y CMP '9' + JA a inválido; luego cascada con JBE.

Practica: E07, E08, E10

E8 · CICLO CON UNA SOLA SALIDA

Lo reconoces por: “se repite mientras no sea crítico”, “monitoreo continuo”, “única salida”.

Receta: etiqueta inicio: arriba, cada rama normal termina en jmp inicio, solo la rama final termina el programa.

Practica: E09

E9 · LEER UNA CADENA

Lo reconoces por: “escriba su nombre”, “ingrese una palabra”, buffer db 20.

Receta: AH = 0Ah con DX = buffer; la cantidad en buffer[1]; los caracteres desde buffer + 2.

Practica: E06, E19

E10 · COLORES CON INT 10h

Lo reconoces por: “cada letra de un color”, arreglo colores db 0Ch, 0Ah….

Receta: por letra: PUSH CX, 03h (cursor), 09h (AL, BL, CX = 1), INC DL, 02h, índices SI/DI, POP CX, LOOP.

Practica: E19

E11 · CONTADOR DE DOS CIFRAS

Lo reconoces por: “convertir el contador a ASCII (soporta ≥ 10)”, “decenas y unidades”.

Receta: AH = 0, BL = 10, DIV BL, BH = AH, si AL = 0 saltar decenas, +30h a cada cifra.

Practica: E14

E12 · REPETIR S/s

Lo reconoces por: “¿Desea repetir el proceso? (S = Sí / Otra tecla = Salir)”.

Receta: leer, CMP 'S' / JE VOLVER, CMP 's' / JE VOLVER, JMP FIN; VOLVER: JMP INICIO; al inicio reiniciar contadores y limpiar pantalla.

Practica: E18

E13 · ARITMÉTICA CON DÍGITOS

Lo reconoces por: “el doble del número”, “la resta (segundo − primero)”.

Receta: leer, − 30h, guardar en variable, operar en AL, + 30h, imprimir con 02h.

Practica: E04, E05

E14 · PROMEDIO Y BANDERAS DE ESTADO

Lo reconoces por: “promedio móvil”, “dos picos seguidos”, variables tipo anterior db 0FFh (centinela) y picoAnt db 0 (bandera).

Receta: suma en AL, shr al, 1, comparar con el umbral; guardar la lectura en anterior para la siguiente vuelta.

Practica: E17

Traza de registros

Como en la hoja de actividades: te dan el estado inicial y una lista de instrucciones, y llenas lo que se pide. Hazlo primero en papel y luego escribe las respuestas para revisarlas. Acepta 3500, 3500h o 0x3500 en hex; −38 o -38 con signo; binario con o sin espacios.

  1. Copia el estado inicial en una tabla con una columna por registro.
  2. Por cada instrucción, escribe solo lo que cambia (el destino, y los implícitos: MUL/DIV tocan AX y DX, PUSH/POP tocan SP, LOOP toca CX).
  3. Mitades: si cambia CH, CX cambia en su byte alto; CL queda igual.
  4. Memoria: calcula la física y anota los bytes (palabra = byte bajo primero).
